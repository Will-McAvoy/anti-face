# 0.5.0 第六轮验收复核

日期：2026-10-08。按用户要求，只把影响使用的缺陷和所选功能未接通列为必修，不追究无关小瑕疵。

源码与发布文件已到0.5.0，七项都有新增模块或UI，但不能认定七项完整交付。备份、安全模式、快速切换存在功能性问题；性能和多屏服务尚有调用链缺口；包一致性失败。

本次 `npm run check` 退出0，184通过、0失败、0跳过，日志 `artifacts/review-050-check.log`。这些测试不能覆盖所有真实入口。

`scripts/smoke-round6.cjs` 经阅读确认是Node模块检查：实例化SafeLaunchManager、调用AppearanceHistory、检查IPC白名单、坐标函数、ZIP读写、性能纯函数和通知能力拒绝。没有启动Electron，没有操作七项UI，没有跨目录完整备份恢复，不是七项端到端验收。未为刷新数字重新执行此脚本。

## 独立复现

脚本：`scripts/review-050.cjs`。结果：`artifacts/review-050-results.json`。使用合成PNG、临时用户目录、真实AssetStore/ThemeLibrary/BackupService，以及服务边界桩；未操作真实宿主。脚本退出0表示观察完成，不是功能通过。

### 1. P1 备份恢复无法还原可读壁纸

真实源AssetStore导入PNG，真实主题库保存引用，导出备份，再向空目标目录恢复。返回commitOk=true、themeCount=1，但AssetStore.read(assetId)失败“壁纸资源不存在”。

原因：BackupService直接写 `userData/assets/<id>`，实际AssetStore需要index记录和 `assets/files/<record.file>`。没有重建索引、引用和元信息。

同一备份再导入时keep-both生成 `imported-...` 非UUID主题ID，ThemeLibrary.load校验时会忽略它。这不是正确去重；冲突副本路径需要使用合法ID并重写引用。

另外代码审查：导出appearance但commit没有恢复它；项目绑定与版本历史也没有对应提交路径。includeRevisions只遍历theme-revisions顶层，漏掉records子目录。资产缺失被静默跳过、仍报成功；暂存目录没有承接实际写入，没有持久化恢复journal；异常回滚不恢复资产且吞回滚异常，不能宣称崩溃事务完整。

### 2. P1 备份检查结果跨进程后不能用于预览

inspection携带Buffer并传给renderer，再由renderer提交previewRestore；后端直接 `.data.toString('utf8')`。独立模拟structuredClone这一序列化边界后Buffer变为Uint8Array，解析报Unexpected non-whitespace character after JSON。

这是序列化边界复现，不是本次实际点击Electron文件对话框的记录。代码路径与UI调用一致；后续须补真实Electron IPC链验证。推荐后端保存检查会话，前端只传令牌，不往返所有文件字节。

### 3. P1 安全模式没有封住应用入口

服务边界复现将StudioService.safeMode=true，通过真实applyEditorDocument入口仍调用宿主apply一次并返回applied。测试替换宿主/存储边界，不声称本次真实窗口被修改。

代码中safeMode主要用于启动时stop自动化和性能evaluate早退；applyEditorDocument/applyLibraryTheme/试穿等未形成统一屏障。enterSafeMode只设置标记、stop自动化，不失效所有在途意图，也没有通知发送层抑制。第一次unclean只记录原因，未见启动选择屏障保障无自动动作。

### 4. P1 快速切换冲突保存失败却报saved

resolveConflict('save')捕获并吞掉commitPreview异常，固定返回 `{ok:true,resolved:'saved'}`。注入disk full后独立复现同样返回成功。discard也存在相同吞错代码。

此外配置校验的shortcut bindings没有quickSwitcher字段，尽管onShortcut已有动作分支，用户无法通过正常配置持久化这一快捷键。属于选定核心入口未接通，不是命名小问题。

## 代码审查确认的未接通能力

### 5. P1/P2 性能策略没有真实运行闭环

- PerformanceService.evaluate未找到生产调用者；contextFor只读取getTargetState，默认normal。
- main没有注入powerMonitor；StudioService创建PerformanceService也只传prefs，电源一直unknown。
- performance:set只更改内存，PreferencesStore默认与validate均未包含performance，重启无法保留策略。
- 没有采样→策略变化→实际重新应用→关闭恢复的调用链。纯函数传powersave能截断blur，不能证明用户开启auto就有效。

### 6. P2 多屏服务只做了局部接线

- DisplayService启动监听，但StudioService未提供onDisplaysChanged处理，默认为空函数。
- updateTargetViewport没有生产调用者。
- quickSwitcher打开时用主屏clamp，但未接主窗/迷你窗在移除屏幕后的救援，以及新服务与宿主上下文失效的完整联动。
- stop没有移除screen监听器，反复生命周期会累积。作为接线修复的一部分处理，不独立扩成优化任务。

### 7. P2 撤销资产保护与通知部分要求只停留在接口

- AppearanceHistory.referencedAssetIds只有定义，未找到生产消费它来保护资产。不应据该函数存在宣称撤销图片生命周期已经保护。
- 通知保留“不可靠来源不报完成”的方向正确，不要求伪造真实completed。新规则的前台context未在真实observeTelemetry调用传入，声音选择/暂停等UI和端到端证据不完整；本轮不能按模块用例称全部体验完成。
- 这些需要补齐已有要求的实际入口，不要求新增云端或复杂通知系统。

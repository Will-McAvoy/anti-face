# Anti Face 第二轮功能升级执行计划 (ROUND2-PLAN)

## 1. 目标与范围

在保持原有 15 套主题、壁纸调节、面板磨砂、设置持久化与撤销换肤安全特性的基础上，分五个阶段实现第二轮升级目标：
1. **F1 实时任务状态**：窗口感知、连接状态、阶段（idle/running/generating/tool_running/waiting_user/completed/failed/cancelled/unknown）、耗时与数据新鲜度。
2. **F2 Token 速度与输出延迟**：首段输出延迟、平均输出速度、滚动输出速度（5s 窗口）。
3. **F3 Token 用量与效率统计**：输入、输出、缓存输入、推理 Token，明确计算口径（包含关系、重试追踪、缓存命中率）。
4. **F4 本地历史与趋势**：安全存储于 Electron userData、筛选（日期/模型/项目/状态）、导出 CSV/JSON、数据保留与清理、隐私保护。
5. **F5 换肤恢复与兼容性增强**：多窗口独立管理、宿主刷新后有界自动恢复（防竞态防覆盖）、版本升级保护、三档性能预设（性能优先/平衡/视觉优先）。

## 2. 阶段规划

### 阶段 M0：基线修复与变更记录（已完成）
- 清理并归档 16 个 OneDrive 冲突文件至 `.backups/conflict-archive-2026-10-03/`。
- 解决 TypeScript TS2717 重复声明错误。
- 确认现有 14 项单元测试通过。
- 针对全新构建的 dist 运行桌面端冒烟测试并通过。
- 建立 `docs/ROUND2-PLAN.md`、`docs/ROUND2-ACCEPTANCE.md`、`docs/CONFLICT-RECOVERY.md`。

### 阶段 M1：数据来源调查与数据合同
- 深度调查 Antigravity 本地可读数据源（CDP 运行时状态、本地日志、应用配置、Hook 机制）。
- 建立数据能力矩阵，明确支持字段、语义与不可得原因。
- 设计归一化事件 Schema 与用量数据结构，区分 delta / cumulative / final。
- 建立测试 Fixture 数据源与契约测试。
- 输出 `docs/TELEMETRY-CAPABILITIES.md`。

### 阶段 M2：实时状态、速度与用量统计 (F1, F2, F3)
- 编写纯函数计算模块：首段输出延迟、区间平均速度、滚动速度（单调时钟、防抖节流）。
- 编写任务状态机：严格单向推进终态，支持乱序/重复事件处理。
- 编写用量与效率统计模块：处理输入包含缓存/互斥、输出包含推理/分离，真实零值与未知区分。
- 前端实现实时面板组件：状态指示器、速度与用量卡片、数据限制 Tooltip 与降级状态展示。
- 后端 IPC 桥接与安全校验，支持取消订阅。
- 编写数值用例与单元测试 (T01 - T08)。

### 阶段 M3：本地历史与趋势 (F4)
- 实现安全本地存储（UserData 隔离子目录，JSONL 单写入队列，原子写入与损坏恢复）。
- 实现历史记录查询、分页、日期与多维度过滤（模型、项目、状态）。
- 实现 CSV / JSON 导出（防 CSV 公式注入）。
- 实现数据保留策略（7/30/90 天）与手动清理功能（带数量与范围预告）。
- 编写存储异常与边界测试 (T10, T11, T13)。

### 阶段 M4：多窗口管理、自动恢复与性能预设 (F5)
- 将单目标会话扩展为多窗口目标管理（targetId 独立会话、独立心跳与所有权）。
- 实现刷新后有界自动恢复机制（Token/Generation 机制防止用户恢复后的竞态反向应用）。
- 升级保护：指纹/版本失配立即进入 suspended 并尽力清理，不强行注入。
- 增加三档性能预设（性能优先 0px/无动画，平衡 12px，视觉优先 24px），并在主题 CSS 中实际生效。
- 编写多窗口与竞态测试 (T12)。

### 阶段 M5：完整验证与交付
